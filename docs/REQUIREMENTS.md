# ArcBody — требования

Документ фиксирует, что сервис обязан делать и с каким качеством. Всё, что
здесь записано, проверяется тестами в `tests/` или прямо названо как
непроверенное.

## 1. Задача

На вход — фотография тела человека. На выход — три вещи, которые можно отдать
провайдеру генерации изображений/видео:

1. **Эмбеддинг тела** — вектор, устойчивый к позе, одежде и кадрированию,
   идентифицирующий телосложение конкретного человека.
2. **Антропометрия** — обхваты, ширины и длины в сантиметрах, с интервалом
   неопределённости у каждой величины.
3. **Условия генерации** — текстовый промпт и control-карты (скелет позы,
   силуэт, нормализованный кроп).

Плюс замыкание петли: проверка, что сгенерированное изображение сохранило то же
тело.

### Что сознательно вне области

- **Идентификация по лицу.** Живёт в существующем сервисе ArcFace. ArcBody
  хранит непрозрачный `external_face_id` и никогда его не интерпретирует.
- **Определение пола, возраста, этничности.** Не измеряется и не угадывается;
  промпт описывает геометрию тела и ничего больше.
- **Медицинские выводы.** BMI попадает в промпт как описание сложения, не как
  оценка здоровья.

## 3. Нефункциональные требования

| ID | Требование | Статус |
|----|-----------|--------|
| НФТ-1 | Работа на CPU без GPU | Выполнено: энкодер 8.0 млн параметров, ~29 мс на кроп |
| НФТ-2 | ~1–2 с на фото | Частично: одно фото без карт ≈ 0.6 с; два фото с картами ≈ 1.7 с. Кодирование PNG нормализованного кропа — заметная доля; отключается флагом `include_control_maps` |
| НФТ-3 | База до ~100 тыс. человек | **Измерено** `scripts/benchmark_gallery.py`: 100 000 человек — поиск 6.0 мс медиана, 7.3 мс p95, индекс 102 МБ, регистрация 1 756/с. Поиск сразу после записи — 6.3 мс благодаря построчному обновлению индекса (до правки: 190 мс уже на 5 000) |
| НФТ-4 | Детерминированность | Выполнено: классический бэкенд полностью детерминирован, синтетический датасет воспроизводим по сиду, необученный энкодер даёт стабильный вектор |
| НФТ-5 | Работоспособность без внешней сети | Выполнено: классический бэкенд не требует весов; YOLO — опциональный extra |
| НФТ-6 | Приватность биометрии | Выполнено: фотографии не сохраняются, хранятся только производные векторы и обмеры; удаление физическое |
| НФТ-7 | Деградация громкая, а не тихая | Выполнено: `/healthz` возвращает `degraded` при необученном энкодере или запасном бэкенде |
| НФТ-8 | Наблюдаемость качества входа | Выполнено: покадровый отчёт о качестве с подсказками уходит в ответ |
| НФТ-9 | Биометрические эндпоинты не обслуживаются анонимно | Выполнено: ключ API как зависимость уровня роутера; в `prod` без ключей сервис не стартует |
| НФТ-10 | Защита от исчерпания ресурсов вызывающим | Частично: токен-бакет 120 запр./мин при всплеске 30. **Лимит на процесс** — за несколькими репликами не глобальный |
| НФТ-11 | Состояние заданий переживает перезапуск | Выполнено: задания и результаты в SQLite; прерванные помечаются неуспешными явно |

## 4. Точность

Измерено на синтетической когорте против **точного** ground truth (тело
задавалось этими же пропорциями). Это регрессионные ориентиры пайплайна, а
**не** заявление о точности на фотографиях людей.

| Величина | 1 ракурс, медиана | 2 ракурса, медиана |
|----------|------------------:|-------------------:|
| Обхват талии | 2.7 % | 1.6 % |
| Обхват бёдер | 3.7 % | 2.6 % |
| Обхват шеи | 2.2 % | 1.2 % |
| Обхват груди | 8.3 % | 7.0 % |
| Обхват бедра | 7.7 % | 6.6 % |
| Обхват плеча (руки) | 7.2 % | 4.0 % |
| Длина ноги | 2.5 % | 3.0 % |
| Внутренний шов | 5.9 % | 5.8 % |

Пороги регрессии зафиксированы в `tests/test_anthropometry.py::TOLERANCE`.

### Эмбеддинг тела

Измерено через сервисный путь (сегментация → кодирование) на 60 невиданных
синтетических людях, 300 снимков. Необученный ствол приведён как пол: без него
число не истолковать.

| Метрика | Необученный | Обученный |
|---------|------------:|----------:|
| AUC верификации | 0.537 | 0.812 |
| EER | 0.470 | 0.275 |
| TAR при FAR 1 % | 0.033 | 0.110 |
| rank-1 | 0.050 | 0.188 |
| mAP | 0.133 | 0.317 |
| MAPE головы пропорций | — | 13.3 % |

Конфигурация: 250 личностей × 8 снимков, 24 эпохи, 8.0 млн параметров, 4 ядра
CPU, ~40 минут. Сигнал телесной идентичности реальный, но до продакшена далеко:
распознавание лиц работает при EER ниже 0.01. Проверяется
`tests/test_encoder_quality.py` (пропускается без чекпоинта) и
`scripts/evaluate_embedding.py`.

## 5. Известные ограничения

1. **Точность на реальных фото не измерена.** Вся числовая валидация — на
   синтетике. Нужна размеченная когорта; см. `docs/ARCHITECTURE.md`.
2. **Детектор YOLO не проверен на фотографиях.** Кодовый путь выполняется
   целиком (веса грузятся, инференс идёт), но синтетические рендеры детектор не
   распознаёт как людей, поэтому качество на реальных снимках не подтверждено.
3. **Эмбеддинг обучен только на синтетике.** Переноса на фотографии не будет
   без дообучения на реальном корпусе. EER 0.275 — доказательство
   работоспособности связки, а не готовый энкодер.
4. **Прерванное перезапуском задание не возобновляется** — намеренно:
   возобновление требовало бы хранить присланные фотографии.
5. **Априорные глубины сечений** — округлённые значения из типичного
   антропометрического диапазона, не подгонка под популяцию. Их и сигмы
   неопределённости нужно перекалибровать на измеренных людях.
