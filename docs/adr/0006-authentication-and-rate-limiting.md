# ADR-0006. Отказ работать анонимно в проде, ограничение частоты на процесс

## Статус
Принято.

## Контекст
Эндпоинты `/v1` возвращают и хранят эмбеддинги и обмеры тела — биометрические
данные. До этого решения аутентификации не было вообще: любой, кто дотянулся до
процесса, мог зарегистрировать человека, найти его в базе и удалить.

## Решение
Ключ API в заголовке `X-API-Key`, проверяемый за постоянное время, как
зависимость **уровня роутера**, а не отдельных маршрутов. Плюс токен-бакет на
вызывающего.

Поведение при пустом списке ключей зависит от окружения:

- `ARCBODY_ENVIRONMENT=prod` — сервис **не стартует**;
- `dev` и `staging` — стартует с выключенной аутентификацией, пишет
  предупреждение в лог и возвращает `degraded` на `/healthz`.

`/healthz` остаётся открытым, но счётчики зарегистрированных людей отдаёт только
аутентифицированному вызывающему.

## Обоснование
Зависимость на роутере, а не на маршруте: новый эндпоинт нельзя добавить
незащищённым, забыв декоратор. Это единственный вариант, где безопасность —
свойство по умолчанию, а не дисциплина.

Отказ стартовать в проде вместо предупреждения: предупреждение в логе никто не
читает, а открытый биометрический API — не та ошибка, которую находят через
неделю. Падение происходит там, где на него смотрят.

Сравнение ключей за постоянное время: обычное `in` по списку выходит на первом
различающемся байте, и по времени ответа ключ восстанавливается побайтово.
Проверяются все кандидаты.

Токен-бакет, а не фиксированное окно: трафик здесь пачками — клиент шлёт
несколько фото и замолкает. Фиксированное окно либо отвергнет пачку, либо
пропустит двойную норму на стыке окон.

## Последствия
- **Ограничение частоты — на процесс.** За несколькими репликами каждая получит
  свой бюджет, так что настроенное число — потолок воркера, а не глобальный.
  Сделать его общим можно только через разделяемое хранилище; выдавать
  per-worker за глобальный было бы хуже, чем это записать.
- Ключи хранятся в переменных окружения открытым текстом. Для однопользователь-
  ского сервиса соразмерно; многопользовательскому нужны хеши и скоупы.
- В логи и в ключи бакета попадает отпечаток вида `key:abcd…24`, но не сам ключ.
- Ответ 429 несёт `Retry-After`: без него клиент повторяет немедленно и
  усугубляет ровно ту ситуацию, за которую его ограничили.
