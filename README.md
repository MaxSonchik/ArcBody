# ArcBody

**Идентификация и обмер тела человека по фотографии — для условной генерации
изображений и видео.**

ArcBody — телесный аналог ArcFace. Та же идея угловой маржи, применённая не к
лицу, а к телу целиком. По фотографии сервис отдаёт три вещи, которые можно
сразу передать GenAI-провайдеру, и одну, которая замыкает петлю:

| | |
|---|---|
| **Эмбеддинг тела** | 256-мерный вектор, устойчивый к позе, одежде и кадрированию |
| **Антропометрия** | обхваты, ширины и длины в сантиметрах, каждая с интервалом и указанием источника |
| **Условия генерации** | текстовый промпт, негативный промпт и три выровненные control-карты |
| **Проверка генерации** | сгенерированное изображение сверяется с зарегистрированным телом: похожесть плюс дельты пропорций |

Распознавание лиц остаётся там, где уже работает. ArcBody хранит непрозрачный
`external_face_id` и никогда его не интерпретирует.

---

## Две вещи, которые надо знать до интеграции

**Фотография определяет форму тела, но не его размер.** Передайте
`stature_cm` — получите сантиметры. Не передадите — получите пропорции. Сервис
не угадывает рост: ошибка роста умножалась бы на каждый обмер, и вы перестали
бы отличать ошибку формы от ошибки масштаба.

**Обхват никогда не измеряется — он реконструируется.** Камера видит ширину
сечения, но не глубину. По одному кадру глубина берётся из популяционного
априора, и величина честно помечается `source: "ellipse_prior"` с широким
интервалом. Пришлите боковой кадр — глубина станет измеренной
(`source: "silhouette"`), а интервал сузится.

## Аутентификация

Эндпоинты `/v1` требуют заголовок `X-API-Key`. Ключи задаются списком:

```bash
export ARCBODY_SECURITY__API_KEYS='key-one,key-two'      # или JSON-массив
curl -H "X-API-Key: key-one" localhost:8000/v1/persons
```

Если ключей нет, поведение зависит от окружения: при `ARCBODY_ENVIRONMENT=prod`
сервис **не стартует**, в остальных случаях стартует с выключенной
аутентификацией и возвращает `degraded` на `/healthz`. Открытый биометрический
API — не та ошибка, которую стоит находить через неделю.

Ограничение частоты — токен-бакет на вызывающего, по умолчанию 120 запросов в
минуту при всплеске до 30. Отказ приходит с кодом 429 и заголовком
`Retry-After`. **Лимит действует на процесс:** за несколькими репликами у
каждой свой бюджет, и настроенное число — потолок воркера, а не глобальный.

`/healthz` остаётся открытым, чтобы оркестратор мог проверять живость, но
счётчики зарегистрированных людей отдаёт только по ключу.

## Быстрый старт

```bash
make install          # venv + пакет + инструменты разработки
make test             # 125 тестов, ~30 c
make demo             # сквозной прогон на синтетическом теле
make serve            # http://localhost:8000/docs
```

Через Docker:

```bash
docker compose up --build
curl localhost:8000/healthz
```

Слим-сборка по умолчанию использует классический силуэтный бэкенд, которому
нужен однотонный фон. Для съёмки «в дикой природе» соберите с боевым
детектором:

```bash
docker compose build --build-arg EXTRAS='[yolo]'
```

## Пример запроса

```bash
curl -sX POST localhost:8000/v1/analyze \
  -H 'Content-Type: application/json' \
  -d '{
        "images": [
          {"content_base64": "'"$(base64 -w0 front.jpg)"'", "view": "front"},
          {"content_base64": "'"$(base64 -w0 side.jpg)"'",  "view": "side"}
        ],
        "stature_cm": 178,
        "weight_kg": 74
      }' | jq '{prompt: .prompt.prompt, waist: .measurements.values.waist_girth}'
```

```json
{
  "prompt": "a person with athletic, V-tapered, BMI 23; broad shoulders, a slim waist and long legs; measurements: height 178 cm, shoulder width 44 cm, chest 98 cm, waist 81 cm, hips 96 cm, inseam 84 cm",
  "waist": {
    "value_cm": 81.4,
    "ci_low_cm": 76.2,
    "ci_high_cm": 86.6,
    "relative_ci": 0.064,
    "source": "silhouette",
    "confidence": 0.81
  }
}
```

Файлом, без base64:

```bash
curl -sX POST localhost:8000/v1/analyze/upload \
  -F files=@front.jpg -F stature_cm=178
```

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET` | `/healthz` | Готовность **и** оговорки, влияющие на качество ответов |
| `POST` | `/v1/analyze` | Обмерить и закодировать тело; вернуть промпт и control-карты |
| `POST` | `/v1/analyze/upload` | То же, обычной multipart-загрузкой |
| `POST` | `/v1/persons/{id}/enroll` | Зарегистрировать тело под идентификатором вызывающей стороны |
| `POST` | `/v1/identify` | Найти ближайшие зарегистрированные тела |
| `POST` | `/v1/persons/{id}/check-generation` | Сверить сгенерированное изображение с зарегистрированным телом |
| `GET` `DELETE` | `/v1/persons/{id}` | Прочитать или полностью удалить профиль |
| `POST` `GET` | `/v1/batch`, `/v1/batch/{job_id}` | Пакетная асинхронная обработка |

Все `/v1` требуют `X-API-Key`, если ключи настроены. `/healthz` — нет.

Полная схема — на `/docs`.

### Замыкание петли качества генерации

```
enroll ──▶ analyze ──▶ промпт + control-карты ──▶ GenAI ──▶ картинка
                                                              │
                          check-generation ◀───────────────────┘
```

Ответ `check-generation` даёт вердикт трёх уровней, потому что отказы бывают
разной природы:

- `consistent` — то же тело в пределах допуска;
- `drifted` — узнаваемо то же тело, но пропорции уехали. Это чинится промптом,
  и `worst_ratios` показывает, каким именно;
- `different_body` — генерацию надо выбросить.

## Как это устроено

```
изображение
   ├─▶ perception  детекция, поза, силуэт        (YOLOv8 или классический бэкенд)
   ├─▶ quality     8 гейтов + подсказки «что переснять»
   ├─▶ measure     пропорции → (× рост) → сантиметры + интервалы
   ├─▶ embed       кроп 128×256 (RGB + маска) → 256-мерный вектор
   └─▶ genai       промпт + скелет + силуэт + нормализованный кроп
```

Подробно — `docs/ARCHITECTURE.md`; решения и их обоснования — `docs/adr/`;
требования с отсылками к тестам — `docs/REQUIREMENTS.md`.

Несколько неочевидных мест:

- **Кроп привязан к росту, а не к рамке детекции.** Рамка расширяется вместе с
  разведёнными руками; привязка к ней заставила бы сеть отменять изменение
  масштаба, не несущее информации о том, чьё это тело.
- **Силуэт подаётся в сеть четвёртым каналом.** Самый дешёвый способ сделать
  эмбеддинг про форму, а не про одежду.
- **Ключевые точки в классическом бэкенде выводятся, а не детектируются**:
  антропометрическая пропорция задаёт полосу поиска, конкретную строку внутри
  неё находит структура силуэта. Все выведенные точки имеют уверенность строго
  ниже единицы.
- **Словесные ярлыки калиброваны по выходам самого оценщика**, а не по учебной
  антропометрии — иначе обычное тело получалось узкоплечим и коротконогим.
  Перегенерация: `make calibrate`.

## Обучение

```bash
make train    # ~900 личностей, ~200 c/эпоху на 4 ядрах CPU
```

Лосс — сумма трёх членов: ArcFace CE, batch-hard triplet и регрессия
пропорций. Одной угловой маржи не хватило: 900-классовый классификатор при 4
снимках на человека даёт каждому центру класса четыре шага градиента за эпоху.
Разбор — `docs/adr/0005-arcface-plus-triplet.md`.

Прогон по умолчанию (250 личностей × 8 снимков, 24 эпохи, ~40 мин на 4 ядрах)
доводит точность на обучении до 0.92, AUC на отложенных личностях до 0.76 и
MAPE головы пропорций до 13 %. Проверить результат независимо:

```bash
python scripts/evaluate_embedding.py --weights weights/arcbody.pt
pytest tests/test_encoder_quality.py     # пропускается без чекпоинта
```

Обучающие данные по умолчанию — параметрический генератор силуэтов. Он даёт
точный ground truth и управляемую идентичность, но **не фотореалистичен**:
обученная только на нём модель на фотографии не перенесётся. Точка подключения
реального корпуса — `FolderBodyDataset`:

```
corpus/
  person_0001/
    front.jpg
    front_mask.png     # опционально
    side.jpg
    ratios.json        # опционально, любое подмножество пропорций
  person_0002/
    ...
```

Цикл обучения при этом не меняется.

## Точность

Всё измерено на синтетической когорте. Это регрессионные ориентиры пайплайна,
**не** заявление о точности на фотографиях людей.

### Обмеры

Медианная ошибка против **точного** ground truth — тела задавались этими же
пропорциями, так что сравнение идёт с истиной, а не с другой оценкой.

| Величина | 1 ракурс | 2 ракурса |
|----------|---------:|----------:|
| Обхват талии | 2.7 % | 1.6 % |
| Обхват бёдер | 3.7 % | 2.6 % |
| Обхват шеи | 2.2 % | 1.2 % |
| Обхват груди | 8.3 % | 7.0 % |
| Длина ноги | 2.5 % | 3.0 % |

### Эмбеддинг

Измерено через **сервисный путь** — сегментация, затем кодирование — на 60
людях, которых модель не видела (300 снимков). Собственная валидация обучения
подаёт сети идеальные маски прямо из рендерера и потому льстит ей;
`scripts/evaluate_embedding.py` этого не делает.

| | Необученный ствол | Обученный |
|---|---:|---:|
| AUC верификации | 0.537 | **0.812** |
| EER | 0.470 | **0.275** |
| TAR при FAR 1 % | 0.033 | 0.110 |
| rank-1 (60 людей) | 0.050 | **0.188** |
| mAP | 0.133 | 0.317 |

Необученный ствол в таблице не для красоты: без него хорошее число невозможно
истолковать.

**Как это читать.** Сигнал телесной идентичности реальный — AUC 0.81 против
0.54 у случайных признаков, и голова пропорций сошлась к 13 % MAPE. Но до
продакшена далеко: система распознавания лиц работает при EER ниже 0.01, здесь
0.275. Модель — 8 млн параметров, обученная 24 эпохи на 250 синтетических
личностях на четырёх ядрах CPU; это доказательство работоспособности связки, а
не готовый энкодер. Чекпоинт в репозиторий не коммитится (32 МБ) — `make train`
воспроизводит его примерно за 40 минут.

## Производительность галереи

Измерено `scripts/benchmark_gallery.py` на 100 000 человек, вектор 256:

| | |
|---|---:|
| Регистрация | 1 756 профилей/с |
| Построение индекса (первый запрос) | 6.5 с |
| Поиск, медиана / p95 | 6.0 мс / 7.3 мс |
| Поиск сразу после записи | 6.3 мс |
| Индекс в памяти | 102 МБ |

Последняя строка — та, ради которой замер и делался. Раньше каждая регистрация
обнуляла индекс, и следующий поиск платил за полную пересборку: на 5 000 человек
это 190 мс против 0.22 мс в установившемся режиме, на 100 000 — секунды. Теперь
индекс обновляется построчно.

## Приватность

Фотографии не сохраняются. Хранятся производный вектор, пропорции и обмеры —
этого достаточно, чтобы узнать человека, и недостаточно, чтобы восстановить
снимок. `DELETE /v1/persons/{id}` — физическое удаление, а не флаг.

Промпт описывает геометрию тела и ничего больше: пол, возраст и этничность не
измеряются и не угадываются.

## Что не сделано

1. **Точность на реальных фотографиях не измерена** — вся числовая валидация
   синтетическая.
2. **Детектор YOLO не проверен на фото**: кодовый путь выполняется целиком,
   но синтетические рендеры детектор людьми не считает.
3. **Эмбеддинг обучен только на синтетике** (AUC 0.81, EER 0.275 на невиданных
   синтетических людях) и не перенесётся на фотографии без дообучения на
   реальном корпусе.
4. **Априоры глубины и сигмы интервалов** требуют калибровки на измеренной
   когорте; до этого сантиметры — оценка, а не обмер.
5. **Прерванное перезапуском пакетное задание не возобновляется** — оно
   помечается неуспешным с объяснением. Возобновление означало бы хранение
   присланных фотографий, чего сервис не делает намеренно.

## Конфигурация

Всё настраивается переменными окружения с префиксом `ARCBODY_`; вложенность —
через `__`.

```bash
ARCBODY_ENVIRONMENT=prod                  # dev | staging | prod
ARCBODY_SECURITY__API_KEYS='k1,k2'        # пусто = без аутентификации (не в prod)
ARCBODY_SECURITY__RATE_LIMIT_PER_MINUTE=120
ARCBODY_SECURITY__RATE_LIMIT_BURST=30
ARCBODY_PERCEPTION__BACKEND=yolo          # auto | yolo | classic
ARCBODY_EMBEDDING__WEIGHTS_PATH=weights/arcbody.pt
ARCBODY_EMBEDDING__MATCH_THRESHOLD=0.55
ARCBODY_GALLERY__DATABASE_PATH=var/arcbody.sqlite3
ARCBODY_QUALITY__REJECT_BELOW=0.45
ARCBODY_GENAI__UNITS=metric               # metric | imperial | both
```

Полный список с комментариями — `arcbody/config.py`.
